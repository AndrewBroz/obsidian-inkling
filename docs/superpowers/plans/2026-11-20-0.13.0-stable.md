# 0.13.0 Stable Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Promote 0.13.0-beta.0 to 0.13.0 with remove-on-resolve on for everyone, CriticMarkup ignored inside fenced code blocks, and conservative automatic cleanup of broken markup.

**Architecture:** A pure `findCodeRegions` feeds an opener-in-fence filter inside `cursorGenerateRanges`, the one function every parse path goes through; the editor state field stores the regions and rebuilds fully when they move. Cleanup is a pure `findDebris` over the *unfiltered* parse, applied by a small Obsidian-level trigger as one undoable plugin-annotated transaction.

**Tech Stack:** TypeScript, CodeMirror 6, Lezer (`@fevol/lang-criticmarkup`), Obsidian API, Svelte settings, Jest (`npx jest`), bun scripts.

**Spec:** `docs/superpowers/specs/2026-11-20-0.13.0-stable-design.md`

## Global Constraints

- Writer default stays `metadata_syntax: "legacy"`; no Release B work.
- Only **fenced** code blocks (``` and ~~~, ≤3 spaces indent, inside `>` quotes/callouts too) are code. Inline code spans and indented blocks are not.
- A range is ignored only when its **opener** lies inside a fenced region.
- Cleanup never deletes non-delimiter text, never touches fenced regions or valid ranges (as paired by the *unfiltered* parse), never acts on a non-active editor, never writes files directly.
- Attribute-block debris requires `author`/`time` (or `a`/`t`); lone `style`/`color` blocks are left alone.
- Every plugin-originated edit carries `pluginEditAnnotation.of(true)`.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Release: push the release tag alone, never `--follow-tags`; never open PRs against upstream.

## Review Focus

1. **Suggested code block** — `{++```js\nx\n```++}` in prose: closing fence followed by `++}` must close the fence; ranges after it still parse. (Task 2 test `closing fence may carry a CriticMarkup closer`.)
2. **Template syntax in prose** — Handlebars `{{!-- note --}}` and Liquid `{{- x -}}` have unpaired-looking `--}`/`-}`; cleanup must leave them. (Task 6 test `template braces are not debris`.)
3. **Unclosed fence** — a note ending mid-fence (sync truncation) hides every opener below it from the parser, and cleanup must not touch those either. (Task 3 test `unclosed fence runs to end`, Task 6 test `debris inside unclosed fence is kept`.)
4. **Typing a fence line in the editor** — turning a paragraph into ``` mid-document flips everything below; incremental state must equal a full parse. (Task 4 fuzz.)
5. **External reload while typing** — sync replaces the doc mid-typing; cleanup must wait for idle and not loop. (Task 7 test `rescheduled while typing; no transaction when clean`.)
